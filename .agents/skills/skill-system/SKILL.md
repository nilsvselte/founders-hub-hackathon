# Skill system

A skill tells an agent how to do one task in this repo. `AGENTS.md` is the entry point and only indexes skills; `docs/` explains the product (see `docs-system`).

## Where skills live

- Project skills: `.agents/skills/<name>/SKILL.md`, committed.
- `.claude/skills` is a relative symlink to `../.agents/skills`, so Claude Code finds the same files. Codex reads `.agents/skills` directly. Keep `.claude/skills` a symlink; a skill added under it lands in `.agents/skills` anyway.
- Every skill is listed in the Skills table of the nearest `AGENTS.md`, with one line on when to use it.

## Finding and using a skill

1. Read the Skills table in `AGENTS.md` (root, plus the subfolder you work in, if it has one).
2. Open `.agents/skills/<name>/SKILL.md` before starting the task it covers, and follow it.
3. Open its reference files only when the step you are on points to them.

## New skill or edit an existing one

- **Edit** when the task is already covered and you are adding a step, a fix, or a gotcha. One meaning lives in one place.
- **New skill** when the task is distinct: someone would ask for it by its own name, and no existing skill's description would trigger for it.
- **Move into a skill** when `AGENTS.md` grows past about 60 lines: take the longest how-to section, turn it into a skill, and leave one row in the Skills table.

## File format

```markdown
---
name: <name>            # same as the folder, lowercase-with-dashes
description: <what it covers>. Use when <trigger 1>, <trigger 2>.
---

# <Title>

Steps in order, then reference the steps need.
```

- The `description` is what makes an agent reach for the skill: lead with the key word, one trigger per distinct case, no synonyms.
- Body under about 150 lines. When it grows, move reference into sibling files (`reference.md`, `api.md`) and link them from the step that needs them.
- Write the target behaviour ("send timestamps with offsets"), not a list of bans. Skip what the agent does by default.
- Point to the source of truth (a README, a config file, `--help`) instead of copying it.
- Public repo: no secrets, tokens, personal emails, or phone numbers.

## Adding a skill

1. Create `.agents/skills/<name>/SKILL.md` in the format above.
2. Add a row to the Skills table in the nearest `AGENTS.md`.
3. Commit both together.

## Nested folders

A subfolder that needs its own rules (for example `marketplace/agent/`) can have:

- `AGENTS.md`: what the folder owns, its rules, and its own Skills table. Agents read it in addition to the root one.
- `CLAUDE.md` containing only `@AGENTS.md` (plus Claude-only lines, if any).
- `.agents/skills/` for skills used only there, and `.claude/skills -> ../.agents/skills` (run `ln -s ../.agents/skills .claude/skills` inside the subfolder).

Put a skill in the subfolder when only work in that folder uses it; otherwise put it at the root. The 60-line rule applies to every `AGENTS.md`.

`device/firmware/AGENTS.md` is the Atech SDK's own guide, generated by `atech new`. Leave it as shipped.
